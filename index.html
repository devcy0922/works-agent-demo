ARCHITECTURE

Two systems, one accountability chain

The components are separated so model judgment, execution authority and human responsibility are not collapsed into one agent loop.

01 · WORKS

Investigation owns context

Normalizes work events, gathers read-only evidence, runs bounded analysis and produces a proposed action with provenance.

  • Triggers & collectors
  • DB / logs / knowledge
  • Agent workflow
  • Approval lifecycle
02 · PINCHQ

Verification owns proof

Turns a proposed change into a typed verification plan, executes narrow runners and aggregates observed evidence.

  • Analyzer
  • Deterministic / adaptive planner
  • Policy validator
  • Command / HTTP / PTY / browser runners
03 · HUMAN

Approval owns consequence

Execution evidence is visible before mutation. Missing evidence remains explicit instead of being converted into model confidence.

  • PASS / FAIL / PARTIAL
  • Evidence review
  • Explicit approval
  • Audit trail
ENGINEERING DECISIONS

Designed around failure, not just the happy path

Human-in-the-loopWhy proposed actions stop before mutation. Evidence-based verificationWhy an LLM judge cannot manufacture PASS. Local-first boundaryWhy sensitive operational context stays close to the operator. Planner / Runner splitWhy planning authority is different from execution authority.
